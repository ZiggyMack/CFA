WHERE MATERIAL GOES
1. source_packet/: prepare one dated, self-contained question and its exact source list. Reference the existing media originals by asset ID/path/hash; do not bulk-copy them here.
2. foreign_returns/raw/: preserve the provider's unedited response, prompt, source selection, date and source/citation references. Grok, Gemini, Flow and outside research all enter as attributed material.
3. review_queue/: reconcile those returns against current project decisions and measured evidence. Record conflicts and unknowns. A persuasive answer is still a proposal.
4. approved_sources/: only explicitly reviewed, scoped material ready to act as current notebook context. An empty folder here means nothing has yet been promoted through this new workflow.
5. promotions/: append the decision that explains what was promoted, for which project/role, by whom, from which bytes, and what it supersedes. Preserve the original answer and prior versions.

A SINGLE ROUND
A. Name the decision. Examples: “Can a mouth close-up improve Hon's grill continuity?” or “Which Boss concept should receive a placement proof?” State what may change, what must stay fixed and the success check. Use ROUND_REQUEST.template.txt. Ask a few decision-relevant questions; do not launch every output type because the old Nyquist template lists it.
B. Assemble sources. Start with current project rules and definitions, the specific approved reference roles, then evidence for this question. Historical alternatives are clearly dated and labeled. A contact sheet is an overview; a frame is a moment; neither proves complete video continuity or audio quality. If a source is unavailable, say so.
C. Verify actual ingestion. Record the notebook ID and exact remote source ID. Open its body and confirm a distinctive fact against the local file; then ask a question that requires that fact and inspect its source citation. Track failed and inactive entries separately from usable entries. Merely uploading a chat attachment or receiving “I understand” is insufficient evidence of persistent visual-source access.
D. Ask with role, constraint and evidence. For example: “Act as our continuity reviewer. Use only the selected current sources. For each observation, identify its asset/source and location or timestamp. Separate direct evidence, interpretation and proposed test. State contradictions and missing material. Do not infer approval from an old filename containing LOCK.” Supply definitions for project-specific terms in the packet.
E. Preserve the raw return. Save the exact prompt and answer, visible citations, selected source IDs, notebook/chat URL and local/remote revision facts. Record tools or web use if visible. Do not re-label a provider's claim as our measurement.
F. Review and route. Check the useful claims against originals/current decisions. Decide accept within scope, hold for evidence, reject, or superseded. Route a small care package to the project or Panhandler Nova: finding, evidence, practical implication, proposed action and unresolved question. A task is sent only when an actual send is recorded; planned is not executed.
G. Promote deliberately. Keep local details in their project. Notebook0 receives only shared methods or explicitly chosen winners with their allowed role and limitations. Update the approval and promotion records before preparing an approved-source revision. A new proposal cannot silently displace an earlier user decision.

Local uploads/copied text should be treated as snapshots unless the actual route proves otherwise. The product also documents image support, while our recorded Lisan JPEG attempts failed. MP4 in its audio-import list means transcription, not demonstrated frame analysis. [G1]

Start with ONE harmless approved text document and ONE local project notebook:
- Prepare revision 1 with a unique marker, such as CFA-NB-PILOT-R1, and a source manifest. Add the approved delivery copy to Drive, then select that actual Drive file in the notebook.
- Record Drive file ID, notebook source ID, local SHA-256 and visible revision. Open the source and ask for the marker plus one specific fact.
- Change only the approved delivery copy to revision 2, preserve revision 1 locally, then check the notebook again. Record elapsed time, whether manual sync was needed, body readback and answer/citation. Do not claim automatic sync until it happens on this account.
- If successful, use the same pattern for approved shared/project text. Do not infer that every file type, folder or new file in Drive will be discovered automatically. A filesystem path is not a remote source ID.

Google says notebooks cannot use another notebook as a source. Gemini notebook chats can also use web/tools; standalone Gemini Notebook is documented as source-grounded. Same-notebook synchronization therefore does not replace our explicit cross-project promotion process. [G2, G3]
