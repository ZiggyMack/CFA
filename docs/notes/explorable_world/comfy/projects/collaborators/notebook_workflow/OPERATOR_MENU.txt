HOW I WILL DRIVE A ROUND
1. Read the latest user decisions and local project records. Select the applicable card and the smallest source set that answers it. The operating_sources.json file maps the cards to real local inputs; a local path is not a notebook source.
2. Add or update the necessary material in actual Sources and verify that it is usable there before relying on it. Select current project sources; select historical alternatives only when comparing them. Do not upload the whole prompt menu as creative canon.
3. Paste the full text between BEGIN PROMPT and END PROMPT into chat, or into the named Studio customization field. Set the controls listed on that card; STUDIO_SETTINGS.txt records current official documentation. A chat request for a deck is not evidence that a Studio deck was created.
4. Let the answer move the work forward: current story, existing material, next choice. Ask another question only for a real ambiguity or a new decision. If selected sources are insufficient, report the missing source; do not fill it from memory.
5. Preserve the result and evidence. Make a short second pass over the SAME result: what useful limitation, method or next-test idea emerged that we did not originally ask for? Extract at most three, with evidence, and keep untested ideas labeled. This is double-dip mining; a second reading is not independent confirmation. For a visual deliverable, check actual images, lettering, names and continuity. Its attractive layout does not make generated artwork a character reference. A text source about a picture can support a description, but cannot substitute for that picture.
6. Send Notebook 0 a concise lesson or scoped winner when useful. It can then prepare a relevant question for another project. Record actual delivery and answers; this folder does not automatically connect notebooks.

WHEN TO REOPEN THE ROUND
After a new intake, a meaningful creative correction, a winner selection, or a failed test that changes the next step. Use only the relevant card. No scheduled automation is created here.

DOUBLE DIPPING, ADAPTED TO CFA
Project A's primary result -> second-pass mining of that result -> a source-backed care package in Notebook 0 -> a bounded question for Project B when its material can help -> its cited answer -> a concrete update or an explicit unresolved item.

Notebook 0 keeps an open-question list and looks for shared usefulness. CHOOSING AN OUTPUT
Chat: make a decision or inspect a conflict.
Report: a usable brief for the next collaborator, with exact material and open work.
Slides: a visual lookbook or story meeting.
Audio: catch up while away from the screen, or hear a critique of the story.
Infographic: keep a simple relationship or workflow map visible.
Video overview: orient someone to the project and its sources.

The Studio video cards are project presentations. Production footage, exact character performance, music timing and lip-sync retain their separate Gemini/Flow/Comfy workflows. Google's Video Overview documentation describes source-based explanation; it does not establish those production controls. This is our workflow distinction, not a claim that cinematic presentation is impossible.
