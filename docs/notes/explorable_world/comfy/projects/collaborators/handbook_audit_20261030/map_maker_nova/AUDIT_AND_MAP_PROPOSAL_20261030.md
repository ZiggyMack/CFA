## Proposed update and adoption mechanism

Reuse the existing Pan cycle: **preserved source → dated delta → owner disposition → adopted teaching → returned navigation link**. Do not introduce a second master ledger. [P3–P4]

For each guide section or bundle entry, record: purpose/question; owner; authoritative source and exact revision/hash; scope; decision/experiment/proposal/history class; what supersedes what; valid-for/invalid-for limits; dependencies; next action; and actual adoption evidence.

1. **Capture a decision once.** Preserve the user's wording or attributed decision record, scope and rationale. Link it from affected maps. Keep exploration, rejected alternatives and superseded decisions accessible as history.
2. **Distil only the reusable lesson.** A local result can suggest a global technique without promoting its media, approvals or a one-result hypothesis. Record remaining uncertainty.
3. **Send a bounded owner delta.** Cite the exact changed section and affected links. CFA reviews production implications; PH Claude the parent teaching; Site UI behavior; Nyquist its general mining method.
4. **Record what actually happened.** Posted, delivered, read, revised, adopted and demonstrated-in-use remain separate. CFA's current owner statement is real lane-specific adoption evidence; receipt of this proposal is not adoption.
5. **Review dependencies when sources change.** Flag affected maps, packages and checks as needing review. Compare authority to derivative, as Nyquist's drift-pair table does. No automatic watcher is proposed or installed.
6. **Expand after one useful proof.** Review this sample's clarity against the Site pilot and Ziggy's feedback, then adapt a storyboard bundle and one collaborator handoff. Preserve a coherent current version with linked history.

If NotebookLM/Gemini synthesis is later scoped, start with this report, the Site pilot/source packet, the existing Pan proposal, relevant ledger passages and selected Nyquist method excerpts. Define a bounded question and require source-located observations, contradictions and unknowns. No mass corpus or new notebook is needed to prepare that request; upload and execution remain unperformed.
