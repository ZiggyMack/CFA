PACKAGE ASSEMBLY
1. Select the actual project/story/shot/take and the intended provider/mode.
   Resolve the latest adopted author decisions and relevant scoped references.
   Pending interview answers and unadopted alternatives remain visibly pending.
2. Assemble only the material relevant to this clip: its action, eyeline,
   camera, light, background, start/end states, boundary and essential nearby
   continuity. Neighbouring context is labelled as context, not extra action.
   Repeat critical requirements in the immediate prompt, even with Sources.
3. Include the exact usable input files required by that mode, with their IDs,
   hashes and roles. A named reference or local path is not a delivered input.
   Starting frames, ingredients, source video and reference-only examples stay
   distinct. Source maturity never substitutes for current preparation checks.
4. Emit the provider-ready prompt, attachment/slot order, supported settings,
   output bound and actual review criteria from this same revision. Translate
   the intended music arc into concrete visible action/pacing; keep master
   music, speech, ambience/effects and provider audio as separate layers.
5. Bind technical details against the actual surface at dispatch. Record what
   is exposed or unknown; unavailable nonessential controls are not new gates.
   A missing necessary input or incompatible mode returns an exact upstream
   gap, never a package falsely labelled ready. Do not silently drop a creative
   requirement to fit a route or invent a supported slot.

ONE CORE, SMALL ROUTE DERIVATIVES
Default: build the package for the chosen route. Generating the other adapters'
text is reasonable where cheap and useful; do not duplicate canonical media or
maintain three artistic drafts. Materially different preparation is done for
the selected route or an explicitly assigned comparison. A/B render requests
and actual submissions retain their existing bounds; package creation alone
does not initiate a generation batch.
For an intentional multi-provider comparison, freeze the common creative core
and common input where applicable, and record each necessary route difference.
Do not mix that comparison with a simultaneous creative rewrite.

WHAT READY MEANS
The selected package contains the material the recipient can actually use,
the prompt and input bindings agree, relevant preparation/checks are current,
and the review asks clear questions about the desired result. Written kitchen
coverage, a ZIP, a green source label or a submitted prompt alone proves none
of those things. Perform the proportionate checks as operator work; settled
reference approvals do not need repeating and no blanket user gate is added.

RETURN AND REVIEW LOOP
Keep the original returned video, actual submitted prompt, selected input
hashes, observed settings and exposed provider/job/conversation identifiers.
Intake measures the file and links it to this package and take, then puts it
into the existing character/scene/technical review with the prewritten success
criteria. Record unknowns, defects and the human verdict separately.
A requested change becomes a new take or an identified technical rerun. For a
creative change, reconcile affected direction/beats/music and regenerate the
prompt and chosen adapter from that new revision. Preserve the previous packet,
result and review; mark dependent packages stale when their inputs change.
