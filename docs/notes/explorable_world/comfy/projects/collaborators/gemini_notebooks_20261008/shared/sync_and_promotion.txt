WHEN TO UPDATE
Prepare a packet after a meaningful user decision, new provider return, measured experiment, reference replacement, stage change or winner promotion. The user's request to maintain context establishes an ongoing workflow preference; this file does not start a scheduled automation or promise background synchronization.

PACKET FIELDS
packet ID; source notebook/project; revision/date; changes since prior packet; superseded IDs/rules; current state; source asset IDs and hashes; actual attachments; selected outputs and approval scope; defects/unknowns; next actions; intended destination notebooks. Include paths for local bookkeeping, but attach actual content where it must be read.

PROPAGATION
1. Record the decision/evidence in CFA and prepare the project update.
2. Apply it to the relevant project notebook and obtain a brief acknowledgement of revision, facts, conflicts and missing attachments.
3. Copy a compact project digest to Notebook 0. Copy full media only for a specifically elevated result and with its source/provenance/review scope.
4. For a changed shared method, update the canonical shared instructions, then apply the same revision to all three notebooks. Record which notebook actually received it; incomplete rollout stays visible.
5. Keep older material as dated history. Explicitly name superseded statements so older chats do not silently regain authority.
