WHY THE EXISTING UI WORKS

library.js storyWorkForAsset() matches either panelAssetIDs or any materials
entry. Each proposed shot contains the actual starting image, received
video, and pinned intake document. The take-two record also includes the retained
take-one video, creating links between both takes without replacing their source. storyMaterialLinks() excludes the current
asset and renders the remaining items as existing data-open viewer buttons.
Consequently a video opens its source and intake, and the starting image opens
its video and intake. The documents receive their exact verified SHA/bytes in
the loader so the existing material hash validator remains strict.

The clips have category videos and one primary video album. A separate
storyboard album references the same IDs through related. Neither duplicate
assets nor new player code is needed. The three shot records have empty
panelAssetIDs/panelIDs and timing unassigned, so Shot progress puts them under
Placement still needed. They do not receive song timestamps or numbered source
panel associations. Reading these connections does not create review state.

  This proposal does not claim a new Flow task card has been added.
- The Gemini output path adds staged clips to Developed video takes, described
  as selected footage beyond preliminary panels. That label is unsuitable here.
- The undownloaded Gemini result is excluded, as are unfinished writer drafts.
- Existing ratings, acceptance scopes, source choices, images, videos, author
