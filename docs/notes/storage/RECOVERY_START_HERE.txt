Restore on a replacement Windows computer
----------------------------------------
1. Sign in to the existing GitHub and backup Drive accounts. Restore into a
   NEW directory on D:, with enough room for the source/media archive plus a
   Git checkout. Do not extract over the only existing copy of a project.
2. Install Git, Python and any required project tools on D:. The former local
   runtime was Python 3.14, with user-site packages disabled; Streamlit's tested
   pin is in apps/creative_studio/requirements.txt. The .cache runtime itself
   is reproducible and is excluded from the new source backup.
3. Clone remote main or restore its source into a separate checkout. Record the
   commit. Git includes old immutable hosted snapshots; do not mistake the
   count of snapshot paths for unique original media or new creative work.
4. Download EVERY part of the chosen dated source backup and its companions.
   Check each part's SHA-256 against its manifest before extraction. Use the
   supplied no-overwrite restore helper for Windows long paths and verify
   restored content hashes. Keep the untouched archives until verified.
5. Reconcile the recovered source working copy with remote main. An older
   local base or absent file is not permission to delete an upstream path.
   Keep recovered review exports and original media unchanged as evidence.
6. If rebuilding the Full Library, prepare the verified design publication
   then run build_portable_dashboard.py using a D: runtime, D: temp/cache and
   dependencies. Its receipt, immutable snapshot and current.json must be
   published together. See apps/creative_studio/README.md.
7. Open the restored site, import complete review JSON through the supported
   UI, and verify notes/ratings/favorites/family direction and original hashes.
   Stale exports are inputs to a field-aware merge, not replacement databases.
8. Check the live Streamlit entry and deployed build after publication:
   https://algaib.streamlit.app/Full_Visual_Library
   Main file: apps/creative_studio/app.py. Requirements: its adjacent file.

Preservation boundaries
-----------------------
The new source backup excludes credential/session recovery trees, installed
dependencies, runtime/shader caches, .git objects and redundant generated
snapshot trees. Git history remains on GitHub. A manifest records exact
included paths and exclusions; selected irreplaceable evidence under .cache
is rescued explicitly. This is a CFA project recovery plan, not a Windows
system image, password-manager backup, or complete backup of sibling projects.
Account sessions and externally stored credentials require account recovery.

Director decisions
------------------
Exploration, favorites, Keep and export selections do not choose a final cast,
location, starting frame or production approval. Preserve reviewer attribution
and the specific scope of every decision. The Oct30 Chris test recovered a

For future maintenance
----------------------
Export review JSON before changing devices or clearing browser data. Keep raw
incoming exports before merging. Commit/push source changes and the exact
publication allowlist, verify the remote commit and live build separately,
then refresh dated source/media backups. Do not erase older backups merely
because a newer file or sync folder is visible. Test restoration periodically.
