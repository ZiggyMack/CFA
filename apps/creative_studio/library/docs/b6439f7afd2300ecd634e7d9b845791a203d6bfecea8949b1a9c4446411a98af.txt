## 0. How download names broke the conversation numbers

| What Nova saw | What it means in chat |
|---|---|
| Folders like `hon-dolo-recent-263-277` / `… (1)` | Zip unpacks; `(1)` = browser duplicate of same zip |
| `HD-EXP-291-cantina-leather-front.jpg` | Chat shorthand **#291** |
| `HD-EXP-LOCK-FACE.jpg` | Chat **LOCK-FACE** (not an EXP number) |
| `ef5d59a6…jpg` (agent attachment stem) | **Same bytes as LOCK-FACE** (SHA-256 `ef5d59a6402eaff568e30bb6a4432b14b90c692ea6758a761c7702c44d457978`) |
| Hash filenames in `unmapped/` | Mid-range EXP stills whose # was never written onto the filename |
| Root MP4s + walk-pack MP4s | Exact copies of the same two clips |

**Rule:** Prefer `HD-EXP-NNN-*.jpg` / `HD-EXP-NNN.jpg` as the conversational ID. Ignore Windows `(1)` folder suffixes. Deduplicate by SHA, not by folder.

Nova’s measurement is correct: **LOCK-FACE ≠ #277 ≠ #289** (different bytes and pixels). The brief’s old “same pixels” claim for #289 was wrong; treat #289 as a **related soft polish**, not a clone.
